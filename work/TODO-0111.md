## Description

Five new fetchers are about to be written (TODO-0112 … TODO-0117), and every one
of them needs exactly what `prepare_fineweb.py` already does:

- batch documents into `SHARD_BYTES` `.txt` files until a `--mb` budget is spent
  (`write_shards`, lines 142-174)
- separate documents with `<|endoftext|>` and neutralize any marker-looking text
  in the source so scraped content cannot inject a false document boundary
  (`MARKER`, line 95)
- clear the previous run's files, scoped to one dataset folder (`clear_previous`)
- write a manifest and report bytes/documents/files with a token projection
  (`report`, `BYTES_PER_TOKEN`)
- optionally write a disjoint held-out slice into `data/eval/corpus`

Copying that into five more scripts is five copies of the marker regex to keep
in sync with the tokenizer's grammar, and five places for the held-out slice to
stop being genuinely disjoint. Factor it first, then write the fetchers on top.

**Wanted.** A module under `scripts/` holding the source-agnostic half: shard
writing to a byte budget, marker neutralization, scoped clearing, manifest
writing, and the projection report. What stays per-script is the part that is
genuinely per-source — which repo, which columns, which quality filter, what
counts as a document.

**The seam to cut on.** `write_shards` already takes an iterator of cleaned
document bodies; that is the right boundary. Each fetcher supplies a generator
of strings and a dataset name, the helper does the rest. `prepare_fineweb.py`'s
`iter_documents` stays in `prepare_fineweb.py` — it knows about `min_score` and
the `metadata` struct, which is FineWeb's schema and nobody else's.

**Do not regress the comments.** The constants in `prepare_fineweb.py` carry
measured values and the reasoning behind them — `BYTES_PER_TOKEN` measured over
real builds, `TEXT_PER_SHARD` measured because the dataset card understates
`download_size` by ~10x, `SHARD_BYTES` chosen to trade directory size against
the pretrain loop's file-granularity shuffle. Those explain *why* and must
travel with the code they explain. The per-shard download figures are
FineWeb-specific and belong to that script, not to the shared module.

Port `prepare_fineweb.py` onto the helper as part of this change, so the
extraction is proven against the script it came from before five more depend on
it.

## Definition of done

- One implementation of shard writing, marker neutralization, scoped clearing

- `prepare_fineweb.py` produces the same output as before the extraction for a

- Measured constants keep the comments that justify them; source-specific
  constants stay in the source-specific script.
