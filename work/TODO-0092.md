## Description

`project_logits` reads the last block's residual stream **directly** into
`w_output`. The blocks are Pre-LN (`x += attn(ln(x))`, `x += ff(ln(x))`), so
nothing normalizes the residual stream itself — its scale grows monotonically
with depth, and the logits grow with it. There is no `1/sqrt(2L)` residual-init
scaling either (`embed()` is plain Glorot), so the only thing bounding the
logits is the f16 clamp in `project_logits`.

Measured on the two pretrains on disk, mean `ln_gamma` of the last block
against layer 0 (from the per-epoch checkpoints):

| epoch | Shakedown 1 (L6) | Balanced 1 (L8) |
|---|---|---|
| 4 | 1.030 | 1.011 |
| 5 (web-text stage) | 1.079 | **1.368** |
| 6 | 1.092 | **1.531** |
| 7 | 1.092 | **1.530** |

The 6-layer run stays flat; the 8-layer run's final-block gain runs away to
2.05 absolute, starting exactly at the stage where the corpus switches to
FineWeb. Larger residual → larger logits → sharper softmax → every wrong
prediction costs disproportionately more nats, which is what turns the ~20-nat
newly-introduced-marker spike documented in `backend/CLAUDE.md` into the ~200
observed on that run.

Shape of the fix: one LayerNorm (`[d]` gamma + beta) applied to the final
hidden state before the projection, forward and backward, trained like any
other parameter. The existing `cuda_layer_norm` / `cuda_layer_norm_backward`
kernels are dimension-generic and can be reused as-is — no new CUDA.

Model files gain two tensors, so `MODEL_VERSION` goes 4 → 5. A v4 file must
keep loading and keep producing what it produced before: those weights trained
with no final norm, and gamma=1/beta=0 is *not* the identity for a LayerNorm,
so synthesizing one would silently change every existing model's output.

## Comments

### Builder · 2026-07-29

`Model` gains `ln_final_gamma`/`ln_final_beta` (`[d]`, gamma=1/beta=0 at init),
applied to the last block's residual stream before `w_output` on both paths:
`final_ln_forward`/`final_ln_backward` on the GPU training path (called from
`run_step` *and* `train_step_kto`, which duplicate the step chain), and at the
end of `forward_seq` for inference — all three CPU-side callers feed `unembed`
directly, so that is the one place it belongs.

**No new CUDA.** `cuda_layer_norm` and `cuda_layer_norm_backward` are
dimension-generic; they just needed a `[d]` gamma/beta and somewhere to put the
activations.

Three things that were not obvious going in, and why they are shaped this way:

- **The activations are dedicated buffers**, not borrowed from `b_sd`. The LN
  backward differentiates against its *input*, so the pre-norm residual has to
  survive `compute_loss` and reach `final_ln_backward` — but the block loop
  reuses `b_sd` before then. Returning `b_dd` would have been worse still:
  `ffn_sublayer_backward` overwrites it at line 85 and then reads its incoming
  `d_dx` at line 100, so aliasing them silently corrupts the residual gradient.
  Three `max_s * d` f16 buffers is ~1.5 MB at ctx 1024; not worth the aliasing
  reasoning.
- **`MODEL_VERSION` 4 → 5, and a v4 model must keep behaving as a v4 model.**
  Those weights trained with no final norm, and a LayerNorm at gamma=1/beta=0 is
  not the identity — synthesizing one changes what every existing model outputs,
  including the Shakedown 1.01 chain. So "absent" is represented as *empty*
  `ln_final_*` and gated everywhere by `Model::has_final_ln`: the forward and
  backward pass the tensor straight through, `upload_weights` skips it,
  `sync_weights_from_gpu` leaves it alone, Adam does not step it, and it is
  excluded from `n_clip` rather than clipped as a permanently-zero buffer.
  `write_model` writes the length, so a fine-tune of a v4 base saves as v5 and
  still records that it has no final norm.
- **The `< MODEL_VERSION` check at the old positional-table read had to become
  `< ROPE_VERSION`.** Bumping the version without that would have made every v4
  file try to read a positional table that is not there and misalign every weight
  after it.

Boundary check added per R10: a final norm present in a file must be exactly `d`
wide, else `read_model` returns `InvalidData` rather than handing a short vector
to the GPU upload.

Tests added — `optimizer.rs::the_final_layer_norm_receives_a_gradient` and
`::a_model_without_a_final_layer_norm_trains_without_one`, plus three
round-trip tests in `serialization.rs`. The first one is the one that matters:
this is the third parameter added between the residual stream and the logits,
and the previous two (absolute positional table, K projection) both shipped
wired into the forward pass while receiving *no* gradient, with the loss curve
still going down in both cases.

Ran: `cargo build` (clean), `cargo clippy -p llm --all-targets` (zero warnings;
the pre-existing `absurd_extreme_comparisons` error in `src/train_worker.rs:597`
is untouched by this change and blocks `clippy` on the `backend` bin only),

**For the Auditor, not fixed here (filed as ISSUE-0093, P0):** `b_dd` is
allocated `Buffer::alloc(d * d)` — `4*d*d` bytes — and used both as the f32
`dWo` gradient and as the f16 `dx` of LN2's backward (`s*d` halves). It only
fits while `s <= 2*d`. `Balanced 1` (ctx 1024, d 256) overran it by 2x on every
layer of every step for its whole run.

*Correction, same day:* the guess above that the overrun lands in `b_dff`/`b_ff`
is wrong — it lands in the file-static `attn`/`ff` scratch in `shaders.cu`,
which is allocated after the workspace and is live within the same layer's
backward. See ISSUE-0093, which now carries the measured A/B. The severity is
unchanged: it corrupts training at `ctx > 2 * d`, so the `ln_gamma` runaway
recorded in this artifact's table was measured on a run that *also* had
corrupted attention gradients. The depth trend across epochs 4→7 is still the
evidence for this issue — it is present in the 6-layer run too, at ctx 512,
where no overrun occurs — but the absolute figure of 2.05 for Balanced 1 should
not be quoted as a clean measurement.
