## Description

`prepare_smoltalk.py` contains the only implementation of the conversion from
markdown to this repo's marker vocabulary: `neutralize`, `inline`,
`starts_block`, `split_blocks`, `to_markup`, `est_tokens`, `build` — roughly
lines 150-353. TODO-0119 needs all of it for smoltalk2, and copying it would
mean two divergent definitions of the format the model is trained on.

That risk is not hypothetical. The converter encodes rules that were learned the
hard way and are recorded in the module docstring:

- underscore emphasis (`_x_`, `__x__`) is deliberately **not** converted,
  because the corpus is 11% code and `sort_tuples` or `__init__` would be
  mangled into italics
- bare URLs are left alone for the same reason
- code spans are lifted out before the emphasis pass and put back after, so
  `**` and `*` inside code survive verbatim
- nested lists are flattened to one level, because there is no rendering
  convention below `list > item`
- user turns must be plain text — the chat template supplies the structural
  markers itself, so `<|user|>`/`<|assistant|>`/`<|system|>` are rejected
  anywhere in the data

A second copy that drifted on any one of those produces training data whose
markup disagrees with what `frontend/lib/message-parser.ts` renders, and the
failure shows up as garbled assistant output long after the fetch.

**Wanted.** Move the source-agnostic conversion into a shared module under
`scripts/`, leaving `prepare_smoltalk.py` with what is genuinely
smol-smoltalk-specific: which repo, its `messages`/`source` schema, the
context-window fitting and the drop tallies.

**Carry the docstring with the code.** The rules above currently live in
`prepare_smoltalk.py`'s module docstring, describing functions that would no
longer be there. They must move with the converter — a rule whose justification
is in another file is a rule that gets "simplified" away.

**Verify against the existing output.** 777 MB of converted conversations sit in
`data/sft/`. Running the extracted converter over a sample of the same source
rows must reproduce the same markup — that is the check that the extraction was
faithful, and it is cheap.

## Definition of done

- One implementation of the markdown→markup conversion, used by
  `prepare_smoltalk.py`.
- The hard-won conversion rules keep their explanations, in the module that now
  holds the code.
- A sample of source rows converts identically before and after the extraction.
