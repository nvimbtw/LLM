## Description

The SFT sets this model is heading toward are written in a technical register —
questions, answers, code spans, step-by-step explanation. Nothing in the current
pretrain corpus looks like that: TinyStories is children's fiction, Wikipedia is
encyclopedic, FineWeb-Edu is filtered toward textbook prose. StackExchange is
the closest large source to the shape of an actual assistant turn, and it is
dialogue-structured without being chat data.

**Wanted.** `scripts/prepare_stackexchange.py` on the TODO-0111 helper, writing
sharded text to `data/input/StackExchange` under a `--mb` budget. Target ~10 GB,
dialable down.

**Decisions the Builder must make and record in the docstring:**

- **Which repo.** RedPajama's and Dolma's StackExchange slices are the usual
  candidates. Verify the repo exists and check its actual schema before writing
  against it — this epic's smoltalk2 fetcher was designed off a verified schema
  and this one should be too. Note the shard count and measured bytes-per-shard,
  as `prepare_fineweb.py` does, because dataset-card `download_size` figures
  have already proven wrong by 10x once in this repo.
- **How a question and its answers become one document.** They must stay
  together — an answer without its question is unanchored text. Concatenate the
  title, body and answers into a single document with a consistent lightweight
  structure, and keep that structure identical across every document so it is a
  learnable pattern rather than noise.
- **Which answers.** Accepted and high-score answers only, or all of them. Score
  is available; a threshold flag mirroring `prepare_fineweb.py`'s `--min-score`
  fits the family.

**Markdown.** Post bodies are markdown or HTML depending on the dump. This is
pretrain text, not SFT, so it does **not** need converting to the marker
vocabulary — but raw HTML tags would be noise worth stripping. Marker
neutralization from the helper is non-negotiable here: a site where people
discuss tokenizers will contain literal `<|endoftext|>`.

## Definition of done

- `data/input/StackExchange` holds sharded text within the requested `--mb`.
- Question and answers land in one document, structured consistently.
- The chosen repo, its verified schema, and the answer-selection rule are stated
  in the docstring.

### Builder · 2026-08-10
Added `scripts/prepare_stackexchange.py` on `donfu/oa-stackexchange`, chosen over the RedPajama/Dolma slices because question/answer pairing and score extraction are already done. Schema verified against the live repo before writing: INSTRUCTION/RESPONSE/SOURCE/METADATA, the last a JSON *string* parsed per row and tolerant of malformed rows.

Question and answer form one document under a fixed `Answer:` separator so the layout is a learnable pattern. Left as plain text, not marker vocabulary — this is pretrain data, and converting here would teach the base model to emit chat markup mid-prose. `--min-score` defaults to 0. Verified with a real 3 MB fetch (3,065 documents).
