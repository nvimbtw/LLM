## Description

The payload of this epic's SFT half: real thinking-mode training data, so a
fine-tune can teach the model to reason before answering and to format its
replies in the marker vocabulary. Explicitly **not** generated by an LLM —
`scripts/generate_sft_llm.py` stays as it is and is not scaled up.

**Source: `HuggingFaceTB/smoltalk2`.** Verified during planning against the
live repo — do not re-derive:

- The `SFT/` config splits cleanly into `*_no_think-*.parquet` and
  `*_think-*.parquet` shards. That split *is* the two-run plan; no filtering is
  needed to separate them.
- Row schema: `messages: [{role, content}]`, `chat_template_kwargs:
  {custom_instructions, enable_thinking, python_tools, xml_tools}`, `source`.
- Thinking traces arrive as a literal `<think>…</think>` block at the **start**
  of assistant content.
- `chat_template_kwargs.custom_instructions` is the system prompt and maps to
  the conversation's `system` field; it is often empty.

**Wanted.** `scripts/prepare_smoltalk2.py` writing two named SFT sets into the
TODO-0106 layout:

    data/sft/smoltalk2-nothink/*.jsonl
    data/sft/smoltalk2-think/*.jsonl

so `POST /sft` with `datasets: ["smoltalk2-nothink"]` and a second run with
`["smoltalk2-think"]` produce two comparable models.

**The conversion, precisely:**

- `<think>…</think>` at the head of an assistant turn becomes
  `<|thinking|>…<|/thinking|>`. The engine's `strip_thinking()`
  (`engine/llm/chat/template.py:100`) removes blocks by exact marker match, so
  a mismatched or unclosed block is silently kept as literal text in what is
  supposed to be reasoning-free output. Drop conversations whose block does not
  close cleanly rather than emitting them.
- Reply bodies go through the TODO-0118 converter. Reasoning content should go
  through it too — the frontend renders the thinking block, and unconverted
  markdown inside it is as wrong there as anywhere else.
- Emit a `budget` field (`low`/`med`/`high`) on think conversations. Those
  markers exist in the template and are currently trained by nothing —
  `prepare_smoltalk.py`'s docstring records that losing them made the
  composer's dropdown "a lever attached to nothing". Derive it from the
  measured length of the reasoning block; state the thresholds in the docstring.
  No-think conversations must carry no budget at all — absence is a real state,
  not a fourth level.
- Reject `<|user|>`/`<|assistant|>`/`<|system|>` appearing in turn text, as
  `prepare_smoltalk.py` already does — the chat template supplies those.
- Fit the context window and drop over-long conversations, reusing
  `prepare_smoltalk.py`'s existing accounting.

**Worth pulling for the web-harness.** Beyond the general conversation shards,
`smolagents_toolcalling_traces_think`, `hermes_function_calling_v1_no_think` and
`xlam_traces_no_think` are tool-calling traces — the closest thing in this
source to the harness the model is meant to drive. Take them, and expose which
shard groups are fetched as a flag rather than hardcoding one list.

**Reasoning traces are long.** OpenThoughts-derived shards in particular carry
blocks far longer than this model's context window. Report the drop tally by
reason, as `prepare_smoltalk.py`'s `report()` does — if most of the think set is
being dropped on length, that is a fact worth seeing at fetch time rather than
inferring from a disappointing run.

## Definition of done

- Both sets exist under `data/sft/` and are listed by `GET /sft/datasets`.
- Every `<think>` block is converted or its conversation dropped; no literal
  `<think>` survives into the output.
- Think conversations carry a `budget`; no-think conversations carry none.
- Tool-calling shards are included, and the shard selection is a flag.
- The fetch reports conversations written and dropped, by reason.

### Builder · 2026-08-10
Added `scripts/prepare_smoltalk2.py` writing `smoltalk2-think` and `smoltalk2-nothink`. The repo's `_think`/`_no_think` shard-group split is used directly; group classification checks `_no_think` first because `OpenThoughts3_1.2M_no_think_no_think` ends with both.

`<think>…</think>` becomes `<|thinking|>…<|/thinking|>`, with reasoning content converted to markup too (the frontend renders that block). A block that does not close cleanly drops the conversation rather than emitting a literal tag. Budgets derived from measured reasoning length at stated thresholds; no-think conversations carry no budget field at all. Structural markers in turn text are rejected. Drop tallies reported by reason.

`--groups` is a flag with `--list-groups` to discover them; the default excludes four groups that are wrong for this model (OpenThoughts3's 113 shards of very long traces, two multilingual sets against an 8k English vocab, and LongAlign's 131k-context data), with the reasoning in the docstring. All three tool-calling groups are included by default.

Verified on a real fetch: `<|thinking|>` and budget markers present and trained in the think set and absent from the no-think set, zero literal `<think>` surviving, zero no-think rows carrying a budget.
