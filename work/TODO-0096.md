## Description

`storage.rs` (101 lines) owns the on-disk layout under `data/` — where corpora,
artifacts, uploads and the raw SFT/preference sets live. It has **no**
`use crate::` dependencies at all and is consumed by eleven other modules
(`training`, `synth`, `autolabel`, `queue`, `train_worker`, and six route
files). It is the natural foundation crate and the correct first extraction.

Move to `crates/storage`, add it to the workspace members and to `backend`'s
dependencies, and rewrite `crate::storage::` → `storage::` at every call site.

Path resolution is unaffected by the move: `storage.rs:23-24` reads an
environment variable and falls back to the *relative* path `"data"`, so
resolution is CWD-based, not `CARGO_MANIFEST_DIR`-based. Do not "fix" this into
a manifest-relative path — that would change where a deployed binary looks for
its data.

Everything `pub` in this module is already used across module boundaries, so the
public surface does not change shape; it just becomes a crate's surface rather
than a binary's internal one.

## Definition of done

- `crates/storage/` exists with its own `Cargo.toml`; `backend/src/storage.rs`
  is gone and `mod storage;` is removed from `main.rs`.
- `grep -rn "crate::storage" backend/src backend/crates` returns nothing.
- `cargo build` and `cargo clippy --all-targets` clean; `cargo test` passes.

## Comments

### Builder · 2026-07-29

`git mv src/storage.rs crates/storage/src/lib.rs`, a dependency-free
`Cargo.toml`, added to `members` and to `backend`'s dependencies, `mod storage;`
dropped from `main.rs`, and all 15 call sites rewritten from `crate::storage` to
`storage`. Path resolution left alone — `root()` still reads `DATA_DIR` and
falls back to the relative `"data"`, so a deployed binary looks in the same
place it did.

Two things the move forced, neither of them cosmetic:

- **`ENV_LOCK` could not stay `#[cfg(test)]`.** That attribute means "when
  *this* crate is compiled as a test", so as a module of `backend` it was
  visible to `backend`'s own tests — which is where `training.rs:2391…` and
  `synth.rs:2073` use it. As a separate crate, `storage` is compiled as a plain
  dependency, `cfg(test)` is false, and the static disappears for exactly the
  consumers it exists to serve. It is now unconditional, with the reasoning
  recorded next to it. This is load-bearing: its own doc comment explains that
  `training` and `synth` previously had a lock each, which guarded nothing
  against the other, and both of those become separate crates in TODO-0099 and
  TODO-0100 — so a per-crate lock would silently reintroduce the intermittent
  failure. Cost is one `Mutex<()>` in the binary.
- **`#![allow(dead_code)]` removed.** It was there because several path helpers
  were written ahead of the pipeline stages that would call them. In a library
  crate a `pub fn` is reachable by definition, so the attribute no longer
  suppresses anything — keeping it would just hide future real dead code.
  `cargo clippy -p storage --all-targets` is clean without it.

`cargo build --tests` is the check that matters here, not `cargo build`: the
`ENV_LOCK` breakage is invisible to a non-test build. 56 backend tests pass,
including the `DATA_DIR` ones that take the lock across the new crate boundary.
