## Description

`GET /datasets` exists so a caller composing a pretrain curriculum can see what
is on disk without guessing folder names. Once SFT sets are selectable
(TODO-0108) the same caller needs the same view for SFT, or the only way to
learn a valid value for `SftConfig.datasets` is to `ls` the data directory.

**Wanted.** A route returning the SFT catalogue from TODO-0106
(`{name, files, bytes}` per set), shaped like the existing `/datasets`
response so the two read alike.

Keep it in the style `main.py`'s docstring insists on: parse, call, return. The
catalogue function belongs to the corpus layer; the route is one line of
delegation. The engine owns this data outright — the fetch scripts fill these
folders, nothing is uploaded through the API — so like `/datasets` this is
read-only.

A count of conversations would be more useful than a count of files, but it
costs a full pass over 777 MB of JSONL per request; file count and bytes are
what `/datasets` reports and they are enough to tell sets apart. Don't add the
expensive field.

## Definition of done

- The route lists every set folder plus `root` if loose `.jsonl` is present.
- Its response shape matches `GET /datasets`.
- No path building or file walking in `main.py` itself.
