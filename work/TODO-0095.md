## Description

First step of EPIC-0094: create the container everything else moves into.

`backend` is a single package, not a workspace — `cargo metadata --no-deps`
lists exactly one member. `llm` and `tokenize` are path dependencies declared as
`{ path = "src/llm" }` and `{ path = "src/tokenize" }`, i.e. dependency crates
living inside the depending package's own `src/` directory. (`cargo test -p llm`
works today only because `-p` can select any package in the resolve graph, not
because there is a workspace.)

Two changes, no logic touched:

1. Add a `[workspace]` section to `backend/Cargo.toml` with `members`, keeping
   `backend` as both the workspace root and the binary package.
2. `git mv backend/src/llm backend/crates/llm` and `backend/src/tokenize
   backend/crates/tokenize`, then update the two path dependencies in
   `backend/Cargo.toml` to `crates/llm` and `crates/tokenize`.

`llm/Cargo.toml`'s own `tokenize = { path = "../tokenize" }` stays correct —
the two remain siblings. Note `llm` and `tokenize` are `edition = "2021"` while
`backend` is `edition = "2024"`; leave that alone, a workspace does not require
a shared edition and changing it is not this artifact's job.

`llm`'s `build.rs` invokes `nvcc` on `src/training/shaders/shaders.cu` — confirm
the paths it builds are manifest-relative (they should be, but a silently stale
`shaders.o` is exactly the failure `backend/CLAUDE.md` warns about under "nvcc
failures must fail the build", so check the object's mtime rather than trusting
a successful link).

## Definition of done

- `cargo metadata --no-deps` lists `backend`, `llm`, `tokenize` as members.
- `backend/src/` no longer contains `llm/` or `tokenize/`.
- `cargo build` clean; `cargo test -p llm -- --test-threads=1` passes
  (including the ignored GPU guards: `attention_learns_to_copy`).
- `shaders.o` is newer than `shaders.cu` after a clean build, proving nvcc
  actually ran from the new location.

### Finding for the Auditor: R7 was never enforced on `llm` or `tokenize`

**`cargo clippy -p llm --all-targets` reported zero warnings before this move
and reports 70 after it, with no source change.** The cause is that `llm` and
`tokenize` were path dependencies *outside* any workspace, and clippy does not
lint dependencies — only workspace members. Naming the package with `-p` did not
change that. Now that they are real members, they are linted for the first time.

The 70 are pre-existing and spread across the whole crate, including files no
recent artifact touched (`tokenize/src/bpe.rs` 9, `training/embed.rs` 3,
`training/device_buffer.rs` 2, `eval/corpus.rs` 2). Largest groups: 28
`unnecessary cast (usize -> usize)`, 6 `manual_is_multiple_of`, 5
`manual_memcpy`, 3 `type_complexity`.

This retroactively weakens the R7 gate on **TODO-0092 and ISSUE-0093** (both now
`done` and committed, `08df59f` / `320e029`). Both Builder comments and both
Verifier comments cite "`cargo clippy -p llm --all-targets` — zero warnings" as
a passed gate. That command was not linting the crate. The code in both is
unaffected — `cargo build`, the test suites and the GPU guards were all real —
but the clippy line in those four comments should be read as vacuous, not as
evidence.

Not fixed here: 70 warnings across two crates is its own artifact, and fixing
them inside a move would make the move unreviewable. Note that until it is
fixed, every Verifier run on an EPIC-0094 child will see these warnings; they
are pre-existing to this epic, not introduced by it.

Three of the 70 fall on lines added by TODO-0092 (`gpu_workspace.rs:554-555`,
`forward.rs:267`). All three are `(expr) as usize` casts that match the
surrounding lines verbatim — the same lint fires on the pre-existing
`cudaMemset` calls directly above and on `backward.rs:135`. They conform to the
file's idiom rather than introducing a new one, so they belong in the sweep with
the rest, not as a correction to TODO-0092.
