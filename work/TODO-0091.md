## Description

The optimizer is plain Adam with **zero weight decay** — neither decoupled
(AdamW) nor L2-in-gradient. The CUDA `adam_kernel`
(`shaders.cu:170-186`) update line is
`updated = w_master[i] - lr * m_hat / (sqrtf(v_hat) + eps)` with no decay term,
and `optimizer.rs` declares `ADAM_BETA1/2/EPS` but no weight-decay constant.
Switch to AdamW: apply **decoupled** weight decay directly to the master weight,
separate from the Adam moment update.

Sibling of TODO-0090 (cosine decay); the two are independent and touch disjoint
files (this one is kernel + `optimizer.rs`, TODO-0090 is `train.rs` only), so
order doesn't matter.

### Shape of the fix

Thread a `weight_decay` parameter end to end and apply it decoupled in the kernel:

1. **Kernel** (`shaders.cu`, `adam_kernel` at :170 and the `cuda_adam` C wrapper
   at :1425): add a `float weight_decay` param. Change the update to decoupled
   AdamW form:
   `updated = w_master[i] - lr * (m_hat / (sqrtf(v_hat) + eps) + weight_decay * w_master[i]);`
   (equivalently `w_master[i] * (1 - lr*weight_decay) - lr * m_hat/(…)`). The
   f32 master stays canonical and the f16 view is refreshed from it exactly as
   now — decay applies to the master.
2. **Rust FFI decl** (`optimizer.rs:15-33`): add `weight_decay: f32` to the
   `cuda_adam` extern signature (matching the C wrapper's new param position).
3. **`gpu_adam_update`** (`optimizer.rs:91-128`): add an `ADAM_WEIGHT_DECAY: f32`
   const alongside the betas (suggest `0.1`, the common AdamW/GPT default; keep
   it a named const so it's tunable). Extend the `adam!` macro to take a
   per-parameter decay value and forward it to `cuda_adam`.
4. **Exclude 1-D parameters from decay** (standard AdamW practice — decaying
   biases and LayerNorm scale/shift hurts). Pass `ADAM_WEIGHT_DECAY` for the
   2-D weight matrices (`dw_output`, `d_embedding`, `wq/wk/wv`, `wo`, `w1`,
   `w2`) and `0.0` for the 1-D params (`db1`, `db2`, `dln_gamma`, `dln_beta`).

### What must stay unchanged

- `gpu_adam_update`'s call site in `train.rs::step_optimizer` — the `lr` passed
  in is unaffected (that's TODO-0090's territory). Weight decay is internal to
  `gpu_adam_update` via the constant, so `step_optimizer` needs no edit.
- Bias-correction, `grad_scale` averaging, the f32-master / f16-view invariant
  (see backend/CLAUDE.md "Mixed-precision"), and the moment buffers — all
  untouched.

### Definition of done

- `cargo build` / `cargo clippy` clean for the `llm` crate (and the CUDA
  compiles via `build.rs`/nvcc if the check environment has it; if not, the
  Verifier should confirm the kernel/wrapper/FFI arg lists line up by
  inspection and note the GPU-build caveat).
- Decoupled decay is applied to 2-D weights only, 1-D params get `0.0`, and the
  update reduces to exactly the old Adam behaviour when `weight_decay == 0`.
- The three arg lists (kernel, C wrapper, Rust extern) agree in order and count.

## Comments
### Builder · 2026-07-18
Implemented decoupled weight decay (AdamW) across the kernel + Rust shim; no
change to `gpu_adam_update`'s public signature or to `train.rs`.

- **Kernel** (`shaders.cu`): added `float weight_decay` to `adam_kernel` and the
  `cuda_adam` C launcher. Update is now decoupled AdamW:
  `updated = w_master - lr * (m_hat/(sqrtf(v_hat)+eps) + weight_decay * w_master)`
  — reduces to plain Adam when `weight_decay == 0`. Decay applies to the f32
  master (canonical); the f16 view is still refreshed from it in the same pass,
  so the ISSUE-0052 mixed-precision invariant is untouched.
- **Rust shim** (`optimizer.rs`): added `weight_decay: f32` to the `cuda_adam`
  extern decl (same arg position, after `eps`); added `ADAM_WEIGHT_DECAY = 0.1`
  const; extended the `adam!` macro to take a per-tensor `$wd`.
- **1-D carve-out**: the 8 groups of 2-D weight matrices (`dw_output`,
  `d_embedding`, `wq/wk/wv`, `wo`, `w1`, `w2`) pass `ADAM_WEIGHT_DECAY`; the
  1-D params (`db1`, `db2`, `dln_gamma`, `dln_beta`) pass `0.0` — the standard
  AdamW practice of not decaying biases / LayerNorm.

**One test updated** (`test_train_step_masked_all_zero_trains_nothing` in
transformer/mod.rs): its old invariant — "an optimizer step after an all-zero
mask leaves weights unchanged" — was true only for plain Adam. Under AdamW,
decoupled decay shrinks every 2-D weight *every* step regardless of gradient
(that's the definition), so a zero-gradient step still scales the embedding by
`(1 - lr*wd)`. Rewrote the assertion to prove exactly what the test is really
for — that masking zeroes the *gradient* — by requiring the only movement to be
that uniform decoupled shrink (`post == base - lr*wd*base` per weight); any
leaked gradient would break the exact ratio. This is a corrected invariant, not
a loosened one.
