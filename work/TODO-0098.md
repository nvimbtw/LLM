## Description

`src/db/` (2,050 lines over eleven files) is the SQL layer: one file per entity,
`sqlx` queries returning `Result<T, sqlx::Error>`, never `HttpResponse`. It
depends on `crypto` (for the create-admin password hash in `mod.rs`) and on
nothing else in the binary.

Move to `crates/db`. **This is the trap-heavy child of EPIC-0094 — read all
three before starting.**

### 1. The migrations path is manifest-relative

`db/mod.rs:21` reads:

```rust
sqlx::migrate!("./src/db/migrations").run(&pool).await?;
```

`migrate!` resolves its argument against `CARGO_MANIFEST_DIR`, which changes
from `backend/` to `backend/crates/db/` the moment this moves. The directory has
to move to `crates/db/migrations` **and** the literal has to become
`"./migrations"`. Get one of the two wrong and it still compiles — the failure
is a panic on startup, or worse, an empty migration set applied silently against
a fresh database. There is no compile-time check for this; the only proof is
running the binary against a clean database.

### 2. `sqlx::query!` needs a database at compile time

The compile-time-checked macros verify against a live server via `DATABASE_URL`,
read from the environment or a `.env` **discovered relative to the crate being
compiled**. `backend/.env` currently serves the whole build. Once the macros
live in `crates/db`, that crate needs its own access — either a `.env` there, or
`SQLX_OFFLINE=true` with a committed `.sqlx/` query cache generated by
`cargo sqlx prepare`. Prefer the offline cache: it makes the build reproducible
without a database, which the current setup is not.

### 3. Public surface

Db structs may carry sensitive fields (`User` holds the password hash) and
`backend/CLAUDE.md` forbids serializing them straight back to a client. Moving
to a crate makes every `pub(crate)` item `pub`. Do not blanket-`pub` to make it
compile — promote deliberately, and keep anything that does not need to cross
the boundary private.

## Definition of done

- `crates/db/` exists with `crates/db/migrations/` inside it; `backend/src/db/`
  is gone and `mod db;` is removed from `main.rs`.
- The `migrate!` literal is `"./migrations"`.
- `grep -rn "crate::db" backend/src backend/crates` returns nothing.
- `cargo build` and `cargo clippy --all-targets` clean; `cargo test` passes.
- **Run the binary against a freshly created empty database and confirm every
  migration applies.** Compile success does not cover this.
