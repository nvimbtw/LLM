## Description

epic — no code lives here directly. Five `db::` submodule types stutter against their module name, violating **R21 (names don't stutter)**:

| Child | Current path | Violation | Proposed name |
|-------|-------------|-----------|---------------|
| ISSUE-0065 | `db::user::User` | `user::User` repeats the module name | `user::UserRow` |
| ISSUE-0066 | `db::chat::Chat` | `chat::Chat` repeats the module name | `chat::ChatRow` |
| ISSUE-0067 | `db::message::Message` | `message::Message` repeats the module name | `message::MessageRow` |
| ISSUE-0068 | `db::model::Model` | `model::Model` repeats the module name | `model::ModelRow` |
| ISSUE-0069 | `db::preset::Preset` | `preset::Preset` repeats the module name | `preset::PresetRow` |

Each is a database row type, so the `Row` suffix adds meaningful context — these are DB entities, not domain model objects. This mirrors the existing convention in `usage.rs` which uses `DailyUsage` and `ModelUsage` (non-stuttering, descriptive names).
