## Description

When the auth token expires, nothing logs the user out — every hook does a raw
`fetch` with `authHeaders()` and maps any non-OK response to a generic error
string without inspecting `response.status` (e.g. `hooks/use-chat.ts:25`,
`components/chat/chats-provider.tsx:51`, `hooks/use-models.ts:112`). The user is
left on a broken page full of "Unable to load" errors until they manually log
out. `clearSession()` is only called from explicit logout
(`hooks/use-auth.ts:87`) and account deletion (`hooks/use-profile.ts:71`).

Shape of the fix: add an authenticated fetch wrapper to `lib/api.ts` (this is
the R15 centralization point) that, on a 401, calls `clearSession()` and
redirects to `/login`, then migrate the hooks' raw `fetch(..., authHeaders())`
calls to it. The WebSocket path needs the same treatment: an auth-rejection on
the socket (`lib/chat-socket.ts:67-74`) currently surfaces as "Connection
error." and should also clear the session and redirect.

Done when: with an expired/invalid token in localStorage, any page that fetches
data lands the user on `/login` with the session cleared, instead of showing
generic errors.
