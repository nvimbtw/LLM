Teaching the model to see: image-input support, end to end

Scope: the model only. Excludes image data pipelines, the Rust backend, and the frontend — but every change below is one the model work must absorb by itself.

Headline answer: roughly 10–13 model-side touch points, ~350–550 lines of new/modified model code, one new dependency, and one checkpoint-version bump. No change to the sampler, the markup grammar, the KV-cache decode loop, or the loss function. The single hardest constraint is not code — it is the 256–512-token context window vs. the ~200 tokens one standard image eats.

The recipe is the standard one (LLaVA-style): a small vision encoder turns the image into a grid of patch embeddings, an MLP projects them into the trunk's 512 dimensions, and they are inserted into the token sequence as if they were text tokens. Everything downstream — causal attention, RoPE, KV caches, sampling, the loss mask — keeps working unchanged.

2. The architecture: how "seeing" works

The image never enters the vocabulary. The flow is:

image bytes ─→ decode, resize to 224×224, normalize      (new: torchvision/Pillow)
                ─→ patchify 224/16 = 14×14 grid          (conv, part of encoder)
                ─→ vision encoder (ViT-ish layers)       (new: VisionEncoder)
                ─→ MLP projector → 512 dims              (new: projector)
                ─→ 196 embedding rows, inserted into the sequence

[<|user|>][img][img][img]…[img][question text…][<|/user|>][<|assistant|>]  ← the only input change
                   ↑ 196 tokens at position 0…195, text continues at 196…

Causality does the rest for free: image tokens sit before the text that describes them, so nobody touches the attention mask. The strategy is identical for pretraining, SFT, and serving — one merged sequence in, one set of logits out.

Classic trap in this repo: the position guard. Transformer.forward raises if pos_offset + seq > ctx_window, and rope_tables are precomputed to exactly ctx_window. A 196-token image inside a 256-window model with a 256-token reserved reply leaves zero room for a question — vision-capable configs must validate ctx_window ≥ image_tokens + text allowance at config time, and realistic image use wants 1024-wide windows (power of two — allowed).

4. What does not need to change

  • The sampler (sample.py) — output is still a token id.
  • The markup grammar (markup.py) and the decode-time block enforcement — replies are still text.
  • The KV-cache decode loop — one prefix pass with images, then the identical per-token loop.
  • The loss (_loss) and the mask machinery — masks already say "train only these positions"; image positions are never targets. With image tokens placed before the text that answers them, even the mask alignment is untouched.
  • The diagnostics collector (diagnostics.py) — it records trunk attention/activations; image tokens ride along naturally.
  • Weight-decay groups — the log_temperature special-casing is name-based and unaffected (the encoder has no temperature parameters).
  • eval/generate.py — the text-only benchmark path keeps working unchanged; a vision suite is a genuinely new artifact, not a modification.
  • RoPE itself — image tokens can use the existing tables at shifted positions; no new positional scheme needed unless you want 2D-aware positions (an easy option to skip).

The honest estimate: the code is ~350–550 lines and a two-afternoon change. The capability is the hard part — a from-scratch encoder at this corpus scale will learn to see only crudely, and a 196-token image inside 512-token context leaves almost no room to talk about what it saw. Vision here is a "bigger context + pretrained encoder" project wearing small-code clothes.

             vision: VisionConfig | None = None):          # ← 4

    self.vision = VisionEncoder(**vision) if vision else None   # ← new module

def forward(self, idx, caches=None, pos_offset=0, images=None):   # ← 4

        vis = self.vision.embed(images)                     # [b, n_patches, d]

    ...                                                     # blocks, ln_final, logits identical

9. Bottom line

Code cost: small. One new module, one fused forward, one version bump, one config block, one dependency — ~400 lines and five files, all in engine/llm/, with the decode loop, loss, sampler, markup and diagnostics untouched. The repo's existing machinery (reserved token slots, mask-already-exists, causality-does-the-work, KV-cache-as-concatenation) was, accidentally, unusually ready for this.

Capability cost: not small. A from-scratch encoder against this repo's one-epoch, ~20×-tokens corpus budget will barely see; the context window must grow to 1024 before an image + a real conversation fit; and the only realistic path to a vision model that actually works is a pretrained-encoder warm start, which the "train everything from the same seed" philosophy of this repo will need a decision to permit. The plan above deliberately puts vision at SFT only — the same seam the thinking budget already uses — so the first version needs no corpus-format changes at all.
