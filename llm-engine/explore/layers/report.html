E9 — Layer ablation: who is actually doing the work

llm-engine/explore/layers · e9_layer_ablation.py · trained diagfix (2L/4H/128d) on a 64-token window

What was done

On the frozen, trained model, we take a real 64-token window and surgically replace one sub-module at a time — block 0 attention, block 0 FFN, block 1 attention, block 1 FFN — with an identity during the forward pass, then measure how much the output breaks:

  • KL divergence per query position vs the intact logits;
  • the next-token cross-entropy change (the model's own loss);
  • top-1 agreement — how often the max-logit token is unchanged.

Clear picture: by far the most load-bearing unit is the FFN of block 0 (~4× the loss increase of block 1's FFN and ~10× that of block 0 attention). Attention in layer 1 matters more than attention in layer 0; the model is very much a "bottom-FFN + top-attention" structure.

Interesting / worrying

  • The ablation asymmetry is not symmetrical with the E2 numbers: block 0 attention is nearly irrelevant (+0.03 CE) to behaviour, while its FFN is critical. So "attention is the whole story" is wrong for this arch; the per-head entropy analysis (E2) only tells half of it.
  • Layer-1 attention is ~5× more disruptive than layer-0 attention — the model routes more information through the second attention block even at this small scale, consistent with a need for per-head temperature (E8).
  • Pruning/deep-reduction intuition holds: a wider first FFN and a stronger top attention would be the best single "small but capable" win for this shape.

Why it would be a good addition

  • A cheap empirical "shape" check in training CI. After N steps, run this 5-second ablation and print the per-unit ΔCE; it surfaces whether an architecture is silently dumping all its work into one block (typical for under-deep models) — exactly the failure E2's diffusion/entropy view cannot spot.
  • Layer-density selection. The rule "prefer a wide first FFN, a strong top attention" is read straight off the table; a recipe like ff_multiplier: [2, 4] + big heads could be validated quickly.
  • Diagnostic gauge in plan.py. A per-subblock "after-train contribution" is a guard: it catches the all-in-one-block training-run pathology early and cheap.

Verdict: a 10-row probe, engine-independent, cheap, and it doubles as a safety belt for any future architecture or width/temperature tweak.

How it changes the workflow

  • The trainer's post-training report can include ΔCE per sub-block, giving everyone a full map of "which unit matters" instead of just the loss curve.
  • Idea evaluation: e.g. replace-FFN width on layer 0 or add a layer deeper — run before/after ablation and compare the "shape".
