System design / product direction

An LLM workspace with the quietness of a notebook.

Slate is an end-to-end environment for talking to models, training them, preparing data, benchmarking results, and putting models through task gyms. Its strongest design idea is editorial restraint: make the work legible, make live state visible, and let the content carry the weight.

Architecture

The frontend is a Next.js App Router application. Server components define the route surface; client components are reserved for browser state, editors, streaming, and interactive data views.

Durable state

REST through a single seam

lib/api.ts centralizes auth headers and configured requests. Domain modules such as models.ts, data.ts, jobs.ts, benchmark.ts, and gyms.ts describe their HTTP shapes. Hooks own loading, error, refresh, and polling behavior.

Live state

One socket per stream

Chat replies, job runs, and gym runs each have a dedicated socket helper. Frames are translated into typed callbacks before reaching UI state.

Composition

Primitives before pages

PageShell, PageHeader, Panel, Card, tabs, dialogs, inputs, and status primitives establish a shared vocabulary. Feature components compose those primitives by domain.

Boundary

Data ownership is explicit

The frontend does not make Python services talk to one another. The backend remains the seam, while each service keeps its own database and domain authority.

Visual system

“Marble light/dark” is a customized Kanagawa lineage: warm paper and softened violet ink in light mode; Dragon blacks, lifted surfaces, and cool pale accents in dark mode.

Color roles

Palette → theme → active mode

Hex values belong to the palette layer. Semantic roles choose the light/dark value. Components only read active roles such as background, foreground, card, primary, border, chart, tier, and sidebar.

Typography

Display contrast

Fraunces carries mastheads and figures. Geist carries interface copy. Geist Mono is reserved for tags, metrics, and technical traces. Eyebrows are uppercase, tracked, and quiet.

Depth

Sheets and furniture

Actionable surfaces are sheets: card fill, a hairline edge, and theme-aware elevation. Summaries are furniture: ruled ledgers with no enclosing box. The distinction creates hierarchy without visual noise.

Shape and rhythm

Hard edges around soft writing

Sheets and controls use restrained 2–3px radii. The composer and chat bubbles are the exception, with pinned, softer radii so the place to write feels distinct from a form field. Spacing follows a 4px unit with semantic roles for sheet, section, stack, inline, and ledger rhythm.

UX / UI upgrades

These are extensions of the current system, not a visual reset. The goal is to make state, intent, and next actions easier to see while keeping the editorial tone quiet.

P0 · orientation

Turn the sidebar into a workspace index

Keep the current compact rail, but add a persistent “workspace pulse” above the footer: active run count, last completed job, and a single “Resume” link. Add keyboard focus and a command/search entry point that can jump to models, chats, jobs, datasets, or actions.

Why: the current navigation is excellent at naming destinations, but live work is split between Admin, Active, and recent conversations.

P0 · state

Make async state a first-class language

Standardize queued, running, paused, failed, and completed across jobs, data pulls, benchmark runs, and gym runs. Pair color with a label, icon, and progress context. Every live surface gets “last updated” and “what happens next.”

P0 · chat

Give the composer a clearer contract

Group model, budget, attachments, and voice under a single “response setup” affordance. Show context usage as a calm meter with a plain-language warning before the limit. Preserve the soft composer shape and frosted treatment.

P1 · compare

Add compare mode for evidence

On Models and Benchmark, let users pin two or three models and compare context, parameter estimate, loss, held-out metrics, and gym scores in one ruled ledger. Keep charts optional; the table is the editorial anchor.

P1 · data

Show the data journey as a thread

Replace the mental jump between Hub, stored dataset, documents, processors, and runs with a breadcrumb-like lineage rail: source → snapshot → cleaned version → training job. Make each stage deep-linkable and expose counts at the transitions.

P1 · responsive

Design mobile as a bottom-sheet workflow

On narrow screens, collapse navigation into a sheet with the same sections and preserve the active-run pulse. Let job configuration and chat settings open as sheets rather than shrinking dense desktop rails into unusable columns.

P2 · trust

Improve recovery and reversibility

For destructive model/chat actions, show impact summaries and offer a short undo window where backend semantics allow it. For failed streams, preserve the transcript and offer retry, reconnect, or copy diagnostics without losing context.

P2 · accessibility

Make the quiet interface more explicit

Audit every icon-only action for an accessible name, ensure live socket updates announce meaningful milestones rather than token noise, add reduced-motion defaults to progress effects, and keep focus rings visible in both themes. Editorial minimalism should remove decoration, not information.

Suggested sequence

Ship the changes in the order that reduces uncertainty for users and avoids a large visual migration.
