engine/explore/tokenizer · e5_tokenizer.py · the shared 8k vocab over the 110k-token corpus

What was done

Measured how the engine's BPE actually spends its 8192 vocab budget on this corpus:

  • reserved special/marker block vs live tokens;
  • token-frequency entropy, top tokens;
  • live-token coverage — how many vocab IDs ever appear;
  • the per-word and per-character token cost for probe words (the/australia/..).

Interesting / worrying

  • 89.8% of vocab is alive — for a 110k-corpus that's high utilisation (a coverage-vs-spread trade). ~10% of IDs never fire, so the budget is slightly over-allocated for this corpus size.
  • Long content nouns (australia, responsibility) pay a 2–12 piece price: the model must spend attention/params re-weighing morpheme bundles to get a single semantic token.
  • with 64 tokens reserved for specials but only 41 markers used, 23 ids are still free to be repurposed for content if ever needed.
  • The 2.62 pieces/word at ~0.24 tokens/char means the tokenizer is already close to byte-level efficiency — so a smarter budget isn't a big win generally; it is concentrated almost entirely on entity names.

Why it would be a good addition

  • Entity prelexing (ties straight into E4): run the capitalised phrase detector once at train-time, reserve the ~96 best slots (the top recurring entities) as single tokens, and byte-fallback the rest. The result is a top(australia)-cheap rate and better gradient locality on real named-entity tasks.
  • Marker reuse. The 23 unused special slots become metadata slots (doc-title, section markers) — a zero-cost way to signal structure through the tokenizer instead of training it to infer structure.

Verdict: tokenizer "entity budget" is the sibling of the KG branch. Both are dataset/tokenizer-only changes: no model code touched; all gains measurable via e5/e4 as before/after.

How it changes the workflow

  • Train-time: tokenizer build runs entity-merging deterministically (a config flag), so downstream vocab files are reproducible.
  • Eval: token-cost metrics (current sheet) become an acceptance gate: "never regress a corpus token count / entity entropy".
  • Pack-SFT/chat formats keep using special markers; content budget is simply spent better.
