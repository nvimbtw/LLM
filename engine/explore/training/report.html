E6 — a real, tiny run through the engine's own loop

engine/explore/training · e6_tiny_run.py · d=64/4h/2L, ctx=64, bs=16, 40 steps, on CPU

What was done

Not a throughput benchmark (settled on the GPU box) but a behavioural harness: drive the actual training loop (bench.build → loop.run) on the real packed corpus and capture the diagnostics the engine itself streams, so every number in these reports can be checked against the engine's own machinery.

Captured: loss curve + lr schedule, grad global norm, per-layer update:weight ratio, attention entropy per head, embedding-centred-cosine (anisotropy surrogate), per-layer activation RMS.

engine/.venv/bin/python engine/explore/training/e6_tiny_run.py > engine/explore/training/e6_tiny_run.json

~4 s on CPU. Scratch checkpoints are written to a temp dir.

  • loss: smooth monotone decrease, no spikes — the whole training path is benign at this scale.
  • update:weight ratio: starts ~1.4e-3 (both layers), ends ~1.2e-4 — the classic 10× squeeze as weights grow. From E2's head-specialisation view: 40 steps isn't enough to finish the copy-head formation the run starts.
  • anisotropy: the embedding mean cosine jumps 0.0 → 0.19 — the first thing the model does is grow the shared direction of E3. A whiten- hook at eval (E3) would counteract precisely this.

How it changes the workflow

  • Adds a "behavioural CI": a 6-second run that fails on regressions (loss climbs, entropy collapses here) — far cheaper than the real train loop.
  • The report-diag columns (entropy, update ratio, anisotropy) can be exported into the engine's existing reporter, giving the same check on long runs.
  • The harness is a place every future idea can land a tiny correctness probe before a branch goes to the GPU box.
